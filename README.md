# Nomi

`LebrosBMO/nomi-ub` — not to be confused with `LebrosBMO/Nomi`, which is a different product.

Mongolian chat assistant for Android, iOS and web. Expo SDK 57 with Expo Router, linked to EAS project `5afdfb0a-1060-4fde-beb8-50bb4a1c9b7a` (owner `tulgaluckystrikes-team`).

This app replaces the single-file pilot in `../nomi-mobile`. The field tools (place checks, location invites, `public/*.html`) and the evaluation data in `../nomi-mobile/eval` stay there.

## Run

```bash
npm install
npx expo start
```

Scan the QR code with Expo Go (phone and laptop on the same Wi-Fi). On Windows PowerShell, if scripts are blocked, use `npx.cmd` instead of `npx`.

After adding native packages, restart with `npx expo start --clear`.

## What it does

- Chat-only interface. The saved conversation keeps the latest 100 messages. Messages are at most 1,000 characters, the same limit the server enforces; the composer says "1000 тэмдэгтэд багтаана уу." at the limit.
- Start screen with six tappable example requests that fill the composer without sending, a status line counted from the catalog and settings ("758 газар · 3 төрөл · AI холбогдоогүй"), and, on the first launch only, three principle lines (remembered as `onboardedAt` in `nomi:pilot:v1`).
- Business search over 758 source-listed records: 671 pharmacies (357 from chain websites, 314 from OpenStreetMap with a phone and a map position; supplement shops such as 4Life and clinics without a pharmacy in their name are left out), 72 tire listings (82 in the sources; the 10 that the phone checks found closed or with a wrong number are left out), 15 materials shops. Tire shops' hours keep only real hours at import (`clean_hours`: "24 цаг" or the stated time ranges, never a Facebook bio), and a shop that comes to the customer ("Дуудлагын", "очно") is flagged `mobile_service`: its card says "Таны байршил дээр очдог" instead of a distance. A card without coordinates in a located search says "Байршил тодорхойгүй, утсаар асуугаарай". Addresses lose Google listing leftovers at import (`clean_address` in scripts/import-directory.py: "Local Business · 2 reviews · 0.4 mi", "Open · Closes 10 PM", times, phones, English categories, plus codes). A night request ("шөнө", "24 цаг", "оройн", Latin and English too: `wantsNight`) shows only places whose own hours claim says open past midnight or around the clock (`openAtNight`; 39 pharmacies, "until 00:00" does not count), nearest first with a position, otherwise 24-hour places first; with none in the district it shows the rest of the city and says so, and the hours are always called unchecked. A search with neither a district nor a landmark is treated as a nearby one: the position is asked for (or used once allowed), and without one Nomi asks for the district instead of listing the city alphabetically. Up to three matches appear inline as cards: verification badge ("Баталгаажсан · date" or "Шалгаагүй"), address, the hours claim labelled "Цаг (баталгаажаагүй):" until verified, a source line derived from the first source URL (Facebook, Google Maps or the hostname; tap opens http/https only), up to three tap-to-call numbers and a map link. Verification status is not invented: `verifiedAt` comes only from a Баталгаажсан outcome in the field tool (23 tire records today, see "Refresh verification data"), every other record keeps `verifiedAt: null`, and prices and opening hours are never promised.
- Nearby search (expo-location): when a request says "ойрхон", Nomi first asks in chat "Ойролцоох газрыг олохын тулд байршлаа ашиглах уу? Байршил зөвхөн энэ утсанд үлдэнэ." with the buttons "Зөвшөөрөх" / "Дүүргээ хэлье". Only "Зөвшөөрөх" reaches the system permission prompt, then one Balanced-accuracy foreground fix with a 10 s limit (background location is never requested), the step "Байршлыг энэ утсан дээр ашиглаж байна", and cards nearest first with "≈ 450 м · алхаж ~8 мин" or "≈ 1.8 км · машинаар ~9 мин" (straight-line distance plus one travel estimate computed on the phone from it: on foot under 1 km, streets ×1.3 at 4.8 km/h; by car from 1 km, ×1.4 at 18 km/h in Ulaanbaatar traffic; under 10 min rounded up, above to 5 min; no route service, so the position still never leaves the phone); records without coordinates come last with "Байршил тодорхойгүй, утсаар асуугаарай" and the reply says how many places of that category have a known location, counted from the catalog. A decline, a refusal or a failed fix answers "Байршил зөвшөөрөгдөөгүй. Дүүрэг эсвэл хороолол хэлбэл хайж өгье." (a request that already names a district is still searched, by name, with "Зайгаар эрэмбэлээгүй."), and nothing asks again in the same session; typing instead of tapping counts as "Дүүргээ хэлье" for that request. The position is used once and dropped: the distances live only in memory (stripped before `nomi:chat:v1` is written), the `/assistant` body carries only the message and the previous intent, and the activity history records `location` without coordinates. Only `locationAsked: true` is kept in `nomi:pilot:v1`; with it and a system permission that is already granted, later sessions locate without asking again, while a user who declined is asked again on the next launch.
- When paired and the AI disclosure is agreed to, the request goes to the server first. If the AI fails for any reason (network, error status, invalid intent, timeout) the offline parser answers, the step "Энгийн хайлт руу шилжлээ" is shown and the reply starts with "AI холбогдсонгүй тул энгийн хайлтаар хариуллаа." (or "Өнөөдрийн AI хязгаар дууссан. Энгийн хайлт ажиллана." when the server's daily cap is reached). Personal commands never reach the server.
- Personal assistant commands (tasks, dated plans in Ulaanbaatar time, explicitly saved memories), stored on the device. See `PERSONAL_ASSISTANT.md`.
- Fresh chat after 2 hours (Section 20): a conversation whose last message is over 2 hours old is put away on launch or on return to the app; "Миний" keeps a "Сүүлд залгасан" list (last 5 places called within 30 days) so nothing found is lost.
- Two tabs (Section 20): "Асуух" is the chat; "Миний" is the personal helper — today's due tasks, reminders and bills first, then the monthly payments with this month's totals (a tap marks paid), open tasks (a tap marks done) and saved memories. The tab badge counts what is waiting today. Both tabs share one set of stores (`src/hooks/use-stores.tsx`), and a tap uses the same functions as the typed command, so they always agree. Typed commands also work in Latin ("ajil nem:", "margaash hiih:", "unuudur hiih:", "ajil 1 ustga", "minii ajluud").
- Own boxes, "Бүртгэл" (Section 21), stored in `nomi:boxes:v1`. The first is spending: "Зардал: 15000 хоол", "8000₮ такси" or the quick add in "Миний" (amount, category chip). "Зардал" gives the month by category; "Зардал 3 устга" removes one. Read on the phone, no AI; a bare number is never spending. The next step lets the AI propose new boxes from a sentence.
- Monthly payments (Section 19), stored on the device in `nomi:payments:v1`: "Төлбөр нэм: түрээс 450000 5" saves a name, an amount in ₮ and the day of the month. "Төлбөрүүд" lists them by day with each one's state (төлсөн / төлөөгүй / өнөөдөр төлөх / хугацаа хэтэрсэн) and the month's total, paid and left; "Төлбөр 1 төлсөн" and "Төлбөр 1 төлөөгүй" mark only the current Ulaanbaatar month, so every month starts unpaid on its own; "Сарын нийт" gives the totals alone; "Төлбөр 1 устга" removes it; "Төлбөр 1-ийг сануул" sets a reminder for the next due day at 10:00. A day the month is too short for (the 31st in February) falls on its last day. Today's plan lists what is due and still unpaid. Amounts never leave the phone and never reach the activity history, which keeps ids only.
- Reminders as local notifications (expo-notifications, no server): "Сануул: маргааш 10:00 дугуй засвар руу залгах", "Ажил 1-ийг маргааш 09:30-д сануул", "Сануулгууд", "Сануулга 1 устга". Times are Ulaanbaatar time and must be ahead ("Энэ цаг өнгөрсөн байна."). The first reminder posts one explanation line, then the system permission prompt; a refusal keeps the reminder in the plan with "Мэдэгдэл зөвшөөрөгдөөгүй тул төлөвлөгөөнд л хадгаллаа.", and on web the reply is "Вэб дээр мэдэгдэл ирэхгүй; төлөвлөгөөнд хадгаллаа." Tapping a delivered notification (or launching Nomi from it) puts "Сануулга: …" in the chat with the buttons "Дууссан" / "30 мин дараа"; a reminder due while Nomi is open is shown as a banner. `nomi:reminders:v1` numbers reminders on its own (commands always name the kind, so "Сануулга 3" and "Ажил 3" never collide), keeps at most 50 waiting, and the activity history records `reminder_set` / `reminder_fired` by id only. `deleteReminders()` in `reminders-storage.ts` cancels every scheduled notification and drops the store; "delete my data" calls it. Not yet tried on a real phone.
- Follow-up after a call (Section 14): a call tap queues `{placeId, calledAt}` in `nomi:followups:v1`. When the app comes back to the foreground after at least 30 s away, or on the next open within 24 hours of the call, Nomi asks once "{Газар} — таны хэрэгтэйг олж өгсөн үү?" (a pharmacy is named as one: "Монос 12 эмийн сан — …") with the buttons "Тийм" / "Үгүй" / "Хаагдсан" / "Утас буруу" / "Дараа". One question per return, the most recent call first; one follow-up per place per day; "Дараа", typing past the question or starting a new conversation asks again on a later return and drops the question after the second time; nothing is asked without a call. Answers are saved in `nomi:reports:v1` as `kind: 'followup'` with `outcome` (`helped`, `not_helped`, `closed`, `wrong_phone`, `later`) and go out with the report export; "Хаагдсан" and "Утас буруу" also mark the card "Та мэдэгдсэн" and rank the place last, so nobody explains twice. The activity history records `followup` by place id. Nomi never calls anyone: the follow-up only asks about the call the user made. The optional notification 30 minutes after a call ("Залгасны дараа асуух") is not built. `deleteFollowups()` in `followups-storage.ts` drops the store; "delete my data" calls it. Not yet tried on a real phone; on desktop web a `tel:` link may not open, but the pending item is still recorded and switching tabs for 30 s brings the question.
- Live step status while Nomi works, with a shimmer and hopping dots. A collapsible summary on each reply shows the steps, elapsed time and AI token count. Each step names real work and stays on screen for at least 0.6 s so it can be read, which adds that pacing to replies.
- Settings (a form sheet) show today's usage: questions, AI requests and tokens on this device, plus the server's shared daily AI cap when connected.
- Pairing token (Section 8): on Android and iOS it is kept in expo-secure-store under `nomi.pairing.token` and the `token` field of `nomi:pilot:v1` stays empty; the first launch after the update moves a token left in AsyncStorage across and blanks it only once the secure copy exists. SecureStore has no web support, so on web the token stays in browser storage and Settings says "Вэб дээр код хөтчийн хадгалалтад байна." The code must be 24–512 characters without spaces.
- AI consent: saving a server URL opens the disclosure "AI-г холбоход таны бичсэн хүсэлт болон өмнөх хүсэлтийн задаргаа Nomi сервер → OpenAI руу явна. …" (route `ai-consent`) with "Зөвшөөрч холбох" / "Болих". Only "Зөвшөөрч холбох" stores `aiConsentAt` and `aiConsentFor` (the provider it named) in `nomi:pilot:v1`, so consent given for an earlier provider asks again; clearing the server URL withdraws it. Paired without consent, nothing is sent: the request is answered on the phone, the reply starts with "AI-г зөвшөөрөөгүй тул энэ утсан дээрх энгийн хайлтаар хариуллаа." and, once per session, the buttons "AI-г холбох" (opens the disclosure) / "Одоо биш" follow; the footer reads "Туршилтын хувилбар · AI-г зөвшөөрөөгүй". Settings → "AI-д юу явах вэ?" shows the consent date.
- Delete my data: Settings → "Миний өгөгдлийг устгах" lists яриа, ажил, санамж, төлбөр, сануулга, мэдэгдэл, үйлдлийн түүх, хэрэглээ, холболт, asks "Бүгдийг устгах уу?", then cancels every scheduled notification, removes the secure token and every `nomi:` key, clears everything on screen and confirms "Бүх өгөгдөл устлаа."; the chat is back at the first-launch welcome. No `delete_all` entry is kept, since a fresh history would be the first thing written back. A partial failure says so and can be repeated.
- Activity history (Settings → "Үйлдлийн түүх"): every action Nomi took on the user's behalf, newest first and grouped by Ulaanbaatar day: calls, map and source taps, AI requests with their token count, task and memory changes by id, requests it could not serve, reports. Ids and counts only, never task, memory, location or conversation text. `nomi:activity:v1` keeps the latest 500 entries.
- First screen (`src/screens/terms-gate.tsx`, drawn over everything until accepted): what Nomi does and what leaves the phone, links to the Terms of Use and Privacy Policy (`src/utils/legal.ts`, version `TERMS_VERSION`), and two buttons. "Зөвшөөрч эхлэх" accepts the terms and the AI disclosure together; "AI-гүйгээр эхлэх" accepts the terms only. The chat never asks about AI (decided 2026-10-07); Settings → "AI-д юу явах вэ?" turns it on or off later. The same documents are routes (`/terms`, `/privacy`): sheets from Settings, and the public pages https://nomi-ub.expo.app/terms and /privacy, which the gate never covers. Drafts: a Mongolian lawyer reviews them and a contact address is added before the public launch.
- "Хуваалцах" on a card opens the system share sheet (React Native `Share`) with the place's name, address, up to three phones, the map link and a link to https://nomi-ub.expo.app (`src/utils/share.ts`). Never the distance, so the sender's position does not leak. An opened share sheet is recorded as `share` in the activity history.
- "Мэдээлэл буруу" on a card opens a form sheet with the reasons Хаагдсан / Утас буруу / Хаяг буруу / Цаг буруу / Өөр and an optional 200-character note. Reports stay on the device in `nomi:reports:v1` (latest 200; the same place and reason within 24 hours is kept once), the card then says "Та мэдэгдсэн", and reported places rank last in later searches on that device. Settings → "Мэдэгдлүүдээ илгээх" writes `nomi-reports-<date>.json` to the cache directory and opens the system share sheet (expo-file-system, expo-sharing); on web the JSON appears in a selectable text box instead. The export holds only id, kind, placeId, reason, outcome, note, createdAt and appVersion.
- Anonymous counters (`src/utils/events.ts`): a card sends `view` once when it is shown and `call`, `map` or `share` when one of those opens, to `POST /api/events` with this install's key. Fire and forget: nothing waits for it, nothing is retried and a failure is dropped in silence. Nothing is sent before the terms are accepted, and nothing but the place id, the Ulaanbaatar month and the kind is stored (`c:<placeId>:<YYYY-MM>`), so the business can be told how often it was shown and called without anybody's message, position or install id being kept. The Privacy Policy says so and `TERMS_VERSION` moved to 2026-10-09.
- Motion uses Reanimated CSS keyframes and transitions, and follows the system reduce-motion setting.

## Categories and catalog (2026-10-08)

**Registry.** `src/data/categories.ts` holds 1,000 service categories in 19 groups (auto, health, home, repair, education, beauty, events, professional, government, sport, rentals, cleaning, transport, travel, pets, childcare, food, shops, other), 47 starred. Each has an id, a Mongolian and an English name, the words people type for it (over 4,000 in all) and the OpenStreetMap tags that mean it. It is generated: edit `scripts/categories.source.json` (merged from OpenStreetMap in UB, the 2GIS/Google/Yandex/Yelp category lists and Mongolian directories such as unegui.mn and the UB city business lists; research in `../research_notes/UB service categories/`), then run `node scripts/build-categories.mjs`. Matching (`src/utils/category-match.ts`) reduces Cyrillic and Latin text to one skeleton ("zaswar" = "засвар"); a word must start a word in the message, the longest phrase wins over a shorter one it overlaps, and two separately named categories make Nomi ask which one. The AI gets the list as "id: Монгол нэр" lines (about 12,000 input tokens a question, mostly cached) and returns an id; the server checks it and corrects near-misses with the same matcher, and a general answer (car repair, a clinic, a plumber) gives way to the one more specific category the user's own words name in the same group or family ("приус засвар" → hybrid repair; `preferNamed`). "Бүх ангилал" (`src/screens/categories.tsx`) lists every category by group with its count and a filter; a tap asks the chat. Each category also says how the customer gets the service (`mode`): 728 are places you go to, 223 come to you ("callout": plumbers, towing, catering, cleaning at home) and 49 are both (tire and car repair, locksmiths, tutors); the list for checking is `../category-modes-review.csv`. A come-to-you search never asks for the phone's position: it puts first those that come to the district asked (the districts a business named, else its own; one that named none may come anywhere), says when none named it, and its cards lead with a large call button and "Таны байршил дээр очдог" instead of an address, distance and map. A "both" search shows the shops as usual and, under "Танай хаяг дээр очиж үйлчилдэг", up to three that come to you. Every answer shows three cards and "Дахиад N харах" opens up to five more in place. The call list asks come-to-you businesses which districts they serve (column "Очдог дүүрэг") instead of where they are.

**Catalog.** 6,370 places in 572 categories (4,481 with a map pin, 2,909 with a phone). Rebuild: `node ../Nomi_All_Prepared_Files/06_OpenStreetMap/fetch-pois.mjs` (every named place in UB), `node scripts/export-categories.mjs`, `python scripts/import-directory.py`. Sources, in order: the original pharmacy, tire and materials files; OpenStreetMap (ODbL), by the registry's tags, then by a category word in the name for loosely tagged places, plus extra categories from secondary tags (`cuisine=korean`, each value of `cuisine=italian;pizza`), long specific phrases in the name, and shorter words naming a service of the same kind as the tag ("…-ӨЭМТ" on a clinic, "Hybrid Service" on a garage; never a bank's name on its ATM or "сургууль" on a university faculty); Buddhist monasteries (by "хийд", "дацан", "temple" in a place-of-worship name) for prayer readings; map tags corrected where the name says more (a numbered хороо is a khoroo office, "өрхийн эмнэлэг" a family health centre, Mobicom branches tagged as foundations are the operator, MIAT and EZNIS sell air tickets, NGO tags count only on names that read as one); the same business drawn twice (same name and category within 100 m of its building outline or 40 m of another point) kept once; web batches in `../Nomi_All_Prepared_Files/07_Web/*.json`, including `social.json` (2026-10-09: Facebook, Instagram and websites searched for all 1,000 categories by collector agents into `08_Social/*.jsonl`, merged by `node scripts/merge-social.mjs`; only businesses whose number was read on a page, title or quote, not shared with a differently named business and not only from an ad site or copied directory, go into the app; the rest wait on the owner's call list `../social-businesses.csv`; coverage per category in `../social-coverage.csv` from `node scripts/check-social.mjs`), and earlier batches collected from allowed sources (the Ministry of Road & Transport auto-service register, the Notary Chamber directory, the UB health department's family-health-centre list, the health insurance agency, the financial regulator, businesses' own sites; never Google Maps, Facebook, Instagram or classified sites). Left out for privacy: directors' personal mobiles in a 2022 audit-licence PDF, home addresses of home child-minders and personal mobiles in a ~2021 IP-attorney list (`education_professional.excluded`), and the lower-confidence state-tender supplier records (`home_repair_review_tender_registry.review`). A place listed again under another service with the same phone and a matching name gains that category (`alsoCategories`); a shared number under a different name is a separate place. Results rank checked places first, then those with a phone, then those with a pin. A district with none of the category shows the rest of the city and says so; a category with no place yet says that plainly. A category with no place of its own offers the general business that often does the job, saying it may and to call first (`FAMILIES` in `src/utils/category-match.ts`: frozen pipes → plumber, a Russian course → language school, tartar cleaning → dentist; then a category in the same group whose name starts with the same specific word; then the group's general place, a garage for car work). 309 of the 428 empty categories get one; the other 119 say plainly that nothing is listed yet. A test keeps every category name matching its own category alone and everyday words ("хийдэг", "хаана байна") matching none. Every new place is "Шалгаагүй" until called: `node scripts/call-list.mjs` writes `../call-list.csv` (places with a phone but no pin first, then unchecked starred ones). `node scripts/phone-check.mjs <dir> "<latin query>" …` runs searches on the plugged-in Pixel and saves screenshots.

## Refresh verification data

After a calling session in the field tool (`../nomi-mobile`, which keeps its notes in `local-data/place-check.json`), rebuild the catalog with three commands from this folder:

```bash
node scripts/export-checks.mjs       # writes data/check-summary.json (version 2) from ../nomi-mobile/local-data/place-check.json
python scripts/import-directory.py   # rebuilds src/data/directory.json and prints the build log (use `py` if `python` is not on the PATH)
node scripts/build-place-index.mjs   # refreshes src/data/place-index.json, which the owner API routes read instead of the catalog
```

The summary holds, per id, only `status`, `checkedAt`, `coordinateStatus` and `location` when a pin was placed. Notes, people, contacts, phone notes, permission answers, addresses, schedules and location history never leave the field tool; `scripts/export-checks.test.ts` checks the file against that allowlist (AC 5.3). `checkedAt` is the date typed in the tool's verification form when there is one, otherwise the time the outcome was last saved, so type the date in the tool to pin it.

The import sets `checkStatus` (the status, or "Шалгаагүй"), sets `verifiedAt` only for Баталгаажсан, leaves out Хаагдсан and Буруу дугаар records, keeps Утсаа аваагүй and Дахин лавлах listed as unverified, and overwrites `latitude`, `longitude` and `mapUrl` only when `coordinateStatus` is Баталгаажсан and a pin exists, adding the flag `coordinates_field_verified`. Flags the check has made false (`not_contact_verified`, `missing_coordinates`, `map_pin_not_field_verified`) are removed at the same time. Tire listings grouped by a shared phone are checked under their top-level id; the related listings inherit the outcome and leave with it. The build log prints counts by status, how many records were left out and any summary id that matched nothing. Running the import twice yields a byte-identical file (AC 5.4); `scripts/import-directory.test.ts` checks that and the rules above through a fixture built from the first session's statuses (AC 5.1).

## AI server

The assistant is one module, `src/server/assistant.ts` (web-standard Request/Response), served two ways: `npm run server` runs it under Node on this laptop (`server/index.ts`), and EAS Hosting serves it at https://nomi-ub.expo.app/api/assistant and `/api/health` through the Expo Router API routes in `src/app/api` (`web.output: "server"`). Hosted settings live in the EAS `production` environment: `OPENAI_API_KEY` (visibility *sensitive*: EAS Hosting cannot read *secret* variables), `OPENAI_MODEL`, `OPENAI_REASONING_EFFORT`, `NOMI_ACCESS_TOKEN` and `MAX_DAILY_AI_REQUESTS` (300). Deploy with `npx expo export --platform web` then `npx eas-cli deploy --prod --environment production`; check that `dist/` holds no value from `.env.local` first. EAS Hosting overwrites the Origin header with its own address (the production alias or the deployment address), so the origin check accepts the deployment's own hosts and the per-minute cap reads `X-Real-IP`. Its caps are per worker instance, so the OpenAI account's monthly budget is the real limit on the bill. A phone that was not paired by hand uses it with an install key (`src/utils/install.ts`): on the first AI request after consent it calls `POST /api/register`, which returns `i1.<random id>.<HMAC-SHA256>` signed with `NOMI_SIGNING_SECRET` (EAS production, *sensitive*, at least 32 characters). No sign-up, nothing about the user is sent, and the server stores nothing: it checks the signature on each request, refuses ids listed in `NOMI_BLOCKED_INSTALLS`, and limits registrations to 5 an hour per address. The key lives in SecureStore (`nomi.install.key`; browser storage `nomi:install:v1` on web), a refused key is replaced once, and "Миний өгөгдлийг устгах" deletes it. A server paired by hand in Settings still takes precedence. Without `NOMI_SIGNING_SECRET`, `/register` answers 503 and the app answers offline.

Copy `.env.example` to `.env.local`. Set `OPENAI_API_KEY` and a random `NOMI_ACCESS_TOKEN` of at least 24 characters, then run `npm run server`. In the app's Settings, enter the server URL and the pairing token. Never enter the OpenAI key there.

The server only sends the user's request and the previous structured intent to OpenAI: the Responses API, model `gpt-6-luna` (`OPENAI_MODEL`), reasoning effort `low`, a strict JSON schema and `store: false`. It never sends the catalog, location or notes. It returns token counts from the response's `usage`, with reasoning tokens counted as output. Why Luna: `../model-eval/RESULTS.md`. Its daily cap (`MAX_DAILY_AI_REQUESTS`, default 200) is process-local and resets at Ulaanbaatar midnight or on restart. Phones need the laptop's LAN address and a deliberate `HOST` and `ALLOWED_ORIGINS`. Before any public use, add HTTPS, per-user limits and real authentication.

## Business owners

A phone-friendly web "app" at https://nomi-ub.expo.app/business, with no store install and no owner accounts or passwords. Three pages and the counters behind them:

- **`/business`** says what Nomi is and that "Таны газар Nomi дээр үнэгүй байна". The owner searches by name or phone (`searchBusinesses` in `src/utils/business.ts`, on the same skeleton `category-match.ts` uses, so "dugui zasvar" finds "Дугуй засвар"), sees how their listing looks in the chat, and sends a correction: phones, hours, an address note, the nine districts served (asked first and plainly for a callout or both category, `categoryMode`), their name, a contact phone and the checkbox "Би энэ газрын эзэн/менежер". `POST /api/business/claim` stores it as a pending claim with an id and a time; the page says Nomi will call the listed number before anything changes. A business not in the catalog yet has its own path, with a category picker over the registry. The partner offer sits on the same page: the "Санал болгож буй" slot, the verified badge and a monthly report, 49,000₮ for 3 months paid upfront, a free month after a month with no calls, at most 3 partners per category per district, and "Түнш болох хүсэлт илгээх" (`POST /api/business/partner`) storing the business with a contact name and phone. No online payment.
- **`/business/report?k=<token>`** is read-only: views, opens, calls, map taps and shares for this month and last month, with a plain line ("Энэ сард 312 хүн таныг харж, 14 хүн залгасан"). The token is the place id and an expiry signed with `NOMI_SIGNING_SECRET` (HMAC-SHA256 over Web Crypto, 92 days); a bad or expired link says so in one sentence. API: `GET /api/business/report?k=`.
- **`/admin`** is the founder's page, behind a token typed in and kept in memory only, sent as a bearer header and compared with `NOMI_ADMIN_TOKEN` by the same constant-time compare the assistant uses. It lists pending claims and partner requests newest first, marks each approved, rejected or called (`GET`/`POST /api/admin/claims`), and makes a report link for any place id (`GET /api/admin/report-link?placeId=`).
- **Counters:** `POST /api/events` takes the same auth as `/api/assistant`, checks the place id against the catalog, and does one `HINCRBY` on `c:<placeId>:<YYYY-MM>` in Ulaanbaatar time, about 120 events a minute per install. The rate-limit keys hold a digest, never the install id, and expire with their window.

Everything is kept through `src/server/store.ts`, an adapter over Supabase's REST API (plain fetch, no SDK, so it runs on the Workers runtime): `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. Three tables and two functions, in `supabase/schema.sql` — paste it into the Supabase SQL editor once: `place_counts` (place id, month, kind, n), `claims` (one row per request, which the Supabase table editor can read and edit directly), and `rate_limits` (one short-lived row per caller per window, which `bump_rate_limit` clears as it goes). Row Level Security is on with no policies, so the anon key reads nothing; only the service key, which never leaves the server, gets through. Without the two variables, `npx expo start` keeps it all in memory (one store shared by the dev server's routes, lost on restart) and production answers 503 `{error:'store_not_configured'}` rather than failing. A database that is unreachable answers 503 too. The routes live in `src/server/portal.ts` and are served by `src/app/api/events+api.ts`, `src/app/api/business/*` and `src/app/api/admin/*`.

Supabase's free plan pauses a project after about a week with no queries, and a paused project has to be restored by hand — which would leave an owner's report link dead. `.github/workflows/supabase-keepalive.yml` makes one harmless query every three days to prevent that; it needs the repository secrets `SUPABASE_URL` and `SUPABASE_ANON_KEY` (the anon key, not the service key — RLS means it reads nothing). On a paid plan, delete the workflow.

Owner corrections reach the catalog by hand, after the call:

```bash
NOMI_ADMIN_TOKEN=… node scripts/export-owner-edits.mjs   # approved claims → data/owner-edits.json (no owner names or contact numbers)
node scripts/apply-owner-edits.mjs                       # phones, hours, address and serviceAreas → src/data/directory.json
node scripts/build-place-index.mjs                       # refresh the place index the owner routes read
```

The apply pass is separate from `scripts/import-directory.py`, so the full import stays byte-identical and can be re-run at any time; run it after. Running it twice changes nothing. `checkStatus` stays "Шалгаагүй" — an owner stating their own hours is not a check — unless an edit carries `phoneVerifiedAt`, the date Nomi reached the business by phone, which marks it "Баталгаажсан" the way the field tool's import does.
